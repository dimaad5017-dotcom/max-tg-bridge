# Что где лежит

Руками ты трогаешь только четыре пронумерованных файла — они и идут по порядку
сверху. Всё остальное мост заводит и читает сам.

```
max-tg-bridge/
│
│   ── Windows: по этим четырём кликаешь, по порядку ──
├── 1-установить.cmd           создаёт окружение и ставит библиотеки
├── 2-настроить.cmd            открывает .env в блокноте
├── 3-войти-в-MAX.cmd          разовый вход по SMS
├── 4-запустить-мост.cmd       запуск, сам поднимается после падения
│
│   ── Mac и Linux: те же четыре шага командами ──
├── mac-linux/
│   ├── 1-install.sh
│   ├── 2-settings.sh
│   ├── 3-login.sh
│   └── 4-run.sh
│
│   ── твои настройки ──
├── .env                       токен, номер и ID группы (в git не попадает)
├── .env.example               образец с пустыми значениями
│
│   ── сама программа, трогать не нужно ──
├── bridge/
│   ├── config.py              чтение .env, приведение номера к +7XXXXXXXXXX
│   ├── login.py               вход в MAX по SMS
│   ├── storage.py             база связок «чат MAX ↔ тема Telegram»
│   ├── run.py                 запускает мост и поднимает его после падения
│   └── main.py                сам мост
├── tests/                     проверки кода, настоящий аккаунт не трогают
├── requirements.txt           список библиотек для установки
├── pyproject.toml             настройки линтера, тестов и данные о проекте
├── deploy/
│   ├── max-tg-bridge.service  готовая служба для Linux-сервера
│   └── ru.max-tg-bridge.plist автозапуск для macOS
├── docs/                      длинные инструкции, вынесенные из README
├── .github/                   проверка кода на каждый пуш и шаблоны обращений
│
│   ── появится само, в git не попадает ──
├── .venv/                     отдельный Python со всеми библиотеками
└── cache/
    ├── max.db                 сессия MAX — ключ от аккаунта
    └── topics.db              какая тема какому чату соответствует
```

Что будет, если удалить:

- **`cache/max.db`** — придётся войти заново по SMS. Иногда это единственный
  способ вылечить испорченную сессию.
- **`cache/topics.db`** — мост забудет, какая тема чему соответствует, и создаст
  новые темы рядом со старыми. Старые придётся удалять руками. Заодно потеряется
  память о том, что уже доставлено, и часть сообщений может прийти повторно.
- **`.env`** — придётся заполнить заново.
